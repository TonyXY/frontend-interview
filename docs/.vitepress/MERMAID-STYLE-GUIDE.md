# Mermaid 图表写作规范（必读）

本规范来源于对本仓库 17 处 mermaid 语法错误和 1 处样式裁剪问题的修复经验。**所有新增/修改的 mermaid 图表必须遵守本规范**，否则会导致渲染失败或文字被裁剪。

## 一、语法红线（违反 = 渲染失败）

以下错误都会导致 mermaid 块**无法渲染**（页面上只显示原始代码），必须避免：

### 1. 箭头必须指向明确的节点，不能指向裸文本

```mermaid
# ❌ 错误：箭头直接接文本，没有节点
flowchart LR
    A --> Partial / Required

# ✅ 正确：文本放进节点
flowchart LR
    A --> B["Partial / Required"]
```

### 2. 节点文本含特殊字符时必须加引号

文本中含以下字符时必须用双引号包裹：`"` `'` `[` `]` `{` `}` `(` `)` `<` `>` `/` `:` `;` `|` 等。

```mermaid
# ❌ 错误：文本含引号和括号
flowchart TD
    C[不仅是"写对"<br/>更是"写得好"]

# ✅ 正确：整体加双引号，内部引号用单引号
flowchart TD
    C["不仅是'写对'<br/>更是'写得好'"]
```

### 3. subgraph 标题含括号时同样要加引号

```mermaid
# ❌ 错误：subgraph 名含括号
flowchart TD
    subgraph 工具类型(分类)
        A --> B
    end

# ✅ 正确
flowchart TD
    subgraph "工具类型(分类)"
        A --> B
    end
```

### 4. 边标签（edge label）不能含未转义的引号或方括号

```mermaid
# ❌ 错误：边标签含引号
flowchart LR
    A -->|他说"你好"| B

# ✅ 正确：用引号包裹整个标签，内部换单引号
flowchart LR
    A -->|"他说'你好'"| B
```

### 5. gantt 日期必须有效且格式正确

```mermaid
# ❌ 错误：无效日期
gantt
    section 基础
    任务A: 2024-02-30, 3d

# ✅ 正确
gantt
    section 基础
    任务A: 2024-02-28, 3d
```

### 6. 节点 ID 不能与文本混淆

```mermaid
# ❌ 错误：直接写文本当节点（含空格/特殊字符视为裸文本）
flowchart LR
    请求类型? --> 简单请求

# ✅ 正确：用 ID + 文本
flowchart LR
    A["请求类型?"] --> B["简单请求"]
```

## 二、样式规范（违反 = 文字被裁剪）

### 节点文字行高问题（已全局修复，但写图时注意）

Mermaid 计算节点高度时假设 `line-height: 1.5`。本仓库已在 `custom.css` 中做了全局修复，**新图无需额外处理**，但以下建议可减少视觉问题：

- **节点文字尽量精简**：单行优先，确实需要多行用 `<br/>`，一般不超过 3 行
- **避免超长文本**：长 URL、长代码片段不适合放节点里，用文字段落说明

### 推荐结构

```mermaid
# ✅ 推荐的流程图写法
flowchart TD
    A["加载页面"] --> B{"是否跨域?"}
    B -->|是| C["预检请求 OPTIONS"]
    B -->|否| D["直接请求"]
    C --> E["服务器返回 CORS 头"]
    E --> F["放行响应"]
```

## 三、提交前自查清单

每篇文档写完 mermaid 块后，按此清单检查：

- [ ] 所有箭头（`-->` `---` `-.->`）指向的是**节点 ID**，不是裸文本
- [ ] 含引号/括号/斜杠的文本都已用 `["..."]` 包裹
- [ ] subgraph 标题含括号时已加引号
- [ ] 边标签内无裸引号（用单引号替代）
- [ ] gantt 日期真实有效
- [ ] 节点文字 ≤ 3 行，无超长内容
- [ ] 代码块用 ` ```mermaid ` 正确包裹
