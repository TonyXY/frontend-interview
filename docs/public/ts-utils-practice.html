实现 MyRequired
简单

实现一个 MyRequired<T>，把类型中所有可选属性变为必选，非可选属性保持不变。内置类型是 Required<T>，请基于映射类型手写实现。

提示
映射类型遍历 keyof T 时，在属性名后加 -? 修饰符即可移除可选标记。注意修饰符的位置在类型声明之前。

答案

解析

映射类型遍历 T 的所有键，逐键重建对象；-? 是移除修饰符的语法，把 a?: string 变成 a: string。 这与内置 Required<T> 的实现完全一致——面试加分项：能说出「Required 就是映射类型 + -?」。

易错点

⚠️ 修饰符位置写错：[K in keyof T]-?: T[K] 中 -? 必须在冒号之前；
⚠️ 方向写反：写成 [K in keyof T]?: T[K] 是给所有属性加上可选，正好相反；
⚠️ 忘记保持原值类型：重建时必须写 T[K]，而不是 any 或空值。

实现 MyOmit
简单

实现 MyOmit<T, K>，从 T 中排除 K 指定的键，返回剩余属性组成的新类型。内置 Omit<T, K> 的官方实现是基于 Pick + Exclude 组合的，请按这个思路实现。

提示
Exclude<keyof T, K> 先算出「除 K 之外的所有键」，再用 Pick 挑出这些键。泛型约束 K extends keyof T 别忘了。

答案

解析

Exclude<keyof T, K>：对联合类型 keyof T 做条件类型分发，剔除 K 中的成员，得到剩余键集合；
Pick<T, ...>：从 T 中只取这些剩余键。两步合起来就是「删掉 K，保留其余」。 这也是官方内置 Omit 的真实实现，直接背诵即可。

易错点

⚠️ Exclude 参数顺序：Exclude<A, B> 表示「A 中排除 B」——第一参是全集 keyof T，第二参是 K，写反就全没了；
⚠️ 泛型约束 K extends keyof T 必须写，否则传入不存在的键编译器不报错（行为错误）；
⚠️ 手写映射版本也可：{ [P in Exclude<keyof T, K>]: T[P] }——面试两种都能答出来是加分项。

实现 MyReturnType
中等

实现 MyReturnType<T>，提取函数类型的返回值类型。要求：不展开 Promise（返回 Promise<boolean> 而非 boolean）；非函数类型返回 never。这是条件类型 + infer 的经典考点。

提示
用 T extends (...args: any[]) => infer R ? R : never 匹配函数签名，infer R 在 true 分支中捕获返回值。注意参数要写成 ...args: any[] 而不是空的 ()。

答案

解析

条件类型 T extends X ? A : B 中，infer R 声明一个「待推断的类型变量」，TS 会从函数签名的返回值位置把真实类型解出来填入 R。 匹配失败（T 不是函数）走 false 分支返回 never。 这是 TS 条件类型最核心的面试题，Parameters、ConstructorParameters、InstanceType 都是同一套路。

易错点

⚠️ infer 只能出现在条件类型的 true 分支里，不能单独在类型顶层使用；
⚠️ 参数必须写 ...args: any[]：只写 () => infer R 只能匹配无参函数，带参函数直接返回 never；
⚠️ 不展开 Promise：期望 Promise<boolean> 原样返回，不要自作主张再套一层 Awaited；
⚠️ 重载函数（overload）取的是最后一个签名的返回值——面试官可能追问。

4
实现 DeepRequired
难

实现 DeepRequired<T>：递归地把所有层级嵌套对象中的可选属性全部变为必选（不只是第一层）。要求：函数类型原样返回；数组递归处理元素；基本类型原样返回。这是「映射类型 + 递归 + 条件类型」的综合题。

提示
先判断 T 是不是函数（函数也是 object，必须最先排除）→ 是不是数组（数组也是 object，其次排除）→ 剩下的 object 用 -? + 递归处理每个属性值 → 基本类型原样返回。

答案

解析

四层判断，顺序是本题关键：
① 函数 → 原样返回（TS 里函数属于 object，若不先排除会被当对象拆解成奇怪的键）；
② 数组 → 用 Array<infer U> 提取元素类型，递归处理元素后重组数组——数组里的对象属性也会被深处理；
③ 其他 object → 映射类型逐键 -? 去可选，并对属性值 递归 调用自身；
④ 基本类型 → 原样返回，终止递归。

易错点

⚠️ 分支顺序：函数和数组必须先于 object 判断，否则 { [K in keyof T] } 会把函数拆成 call/apply/...、把数组拆成 0/1/length 的怪形状；
⚠️ 数组元素也要深处理：写成 T extends Array<infer U> ? DeepRequired<U>[] 才能让数组里的对象属性也变必选，而不是直接把数组当整体返回；
⚠️ 忘记递归：只做 -? 不递归的话，嵌套层的内层可选属性不会被处理——这正是「Deep」的意义；
⚠️ 元组 [a, b] 会被当作普通数组（形状退化为数组）——如需严格保留元组形状，需加 IsTuple 辅助类型判断（加分项，了解即可）；
⚠️ 循环引用类型会无限递归（TS 会报深度上限）——可主动说明此限制。

实现 PickByValue
难

实现 PickByValue<T, V>：根据值的类型筛选属性，只保留「值类型匹配 V」的键。比如 PickByValue<T, string> 只保留值为 string 的属性，其余键丢弃。这是「映射类型 + key 重映射（as 子句）+ 条件类型」的综合题。

提示
映射类型遍历 keyof T 时用 as 子句重映射键名：T[K] extends V 命中则保留 K，否则重映射为 never（键被过滤）。TS 4.1+ 支持。

答案

解析

key 重映射：映射类型里 [K in keyof T as NewKey] 可以重命名/过滤键。当 T[K] extends V 为 true 时保留原键 K；为 false 时把键重映射为 never——键变成 never 即被过滤，属性直接消失。 值部分仍是 T[K]，完整保留原类型。

易错点

⚠️ 不能只写 { [K in keyof T]: T[K] extends V ? K : never }：这不会过滤键，而是把值改成了键名/never——过滤键必须用 as 重映射；
⚠️ 老版本写法（无 as 子句）：Pick<T, { [K in keyof T]: T[K] extends V ? K : never }[keyof T]>——把命中键组成联合再 Pick，了解即可；
⚠️ 子类型匹配：若属性值是字面量 name: 'foo'，PickByValue<T, string> 也会保留它（'foo' extends string 成立）；若 V 是 string 而属性是 string | undefined，则不会匹配（联合类型需整体 extends）。
